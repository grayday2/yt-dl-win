# SPEC — как система ведёт себя СЕЙЧАС

Это контракт текущего поведения. README §5.5.X — журнал эволюции (зачем так,
а не иначе); HISTORY.txt — хронология релизов; SPEC.md — что верно на этой
версии. Противоречие между SPEC и кодом = баг в одном из них.

## 1. Слои

    [браузер] userscript (Tampermonkey/Violentmonkey, Firefox в приоритете)
      ├─ хуки fetch/xhr: state.byVideo (player-ответы), state.streams (качание),
      │  state.pageQueue (get_queue), state.playback
      ├─ панель: 4 режима (auto/ytdlp/resolve/replay + direct внутри), chips,
      │  секции <details>, «стоп» красная в общем ряду кнопок
      ├─ сбор списков (см. §4) и метаданные строк (см. §3)
      └─ режим record УДАЛЁН в 0.6.16 (старый cfg.mode=record → resolve)

    [транспорт] http://127.0.0.1:8765 (по умолчанию), localhost-only, токен опционально
      POST /media · POST /job (url|playlist|browser) · GET /job/<id>
      POST /job/<id>/cancel · GET /has?ids= · GET/POST /archive · POST /archive/reset
      GET /cover · POST /log (зеркало панели, дедуп 2 c) · GET /hello · GET /shutdown

    [компаньон] server/companion.py (один процесс, одна worker-очередь)
      handle_media / handle_url / handle_playlist / handle_browser
      ThrottleQueue (persistent, интервалы не дедлайны) · _WIN (sticky клиент)
      kill_children / _run_tracked (каждый дитя-процесс виден и убиваем)

    [supervisor] ytm.bat → app/control.py: serve/stop/kill/restart/status/
      selftest/log/report/deno/uninstall; процессы ищутся по CommandLine.

## 2. Пайплайн финализации (порядок инвариантен на всех точках входа)

    resolve bytes → sniff_container (магические байты, не Content-Type)
    → remux/convert (opus→.opus copy; webm→m4a/mp3; copy = как есть)
    → verify (ffmpeg -xerror; не декодируется = Error и НЕ в архив)
    → dest_for + dest_taken ДО переноса (занято = «уже есть», без « (1)»)
    → move в папку вывода → write_tags (+read-back) → обложка → archive.add
    Архив «уже скачано» пополняется ТОЛЬКО успешными файлами; «skip» решается
    по архиву до закачки. Никаких промптов о сохранении. Никаких суффиксов
    « (1)»/« (2)» нигде: повторный путь = Skipped, не переименование.

## 3. Метаданные — каскад источников правды

    1) DOM-строка страницы (отрисовано = правда): title/byline/album
    2) payload get_queue — добирает поля, которых DOM не дал (по videoId)
    3) info.json yt-dlp (год/жанр/дорожка/album-artist) — только пустые слоты
    Правила:
    • Название (TIT2 и имя файла) = ТОЛЬКО трек, без альбома и без «Артист - »;
      префикс срезается при всех склейках артиста («, », « и », « & », « feat. »)
      и гибко к NBSP/двойным пробелам.
    • Исполнители: «A и B» → «A, B» (список через запятую). Альбом/названия
      склейками не режутся.
    • Ноль — не данные: 0, "0", [0], "0/12" в теги не пишутся никогда.
    • «Дорожка» берётся только из info.json, если реально есть; не выдумывается.
    • Альбом-артист (TPE2/aART) = артист трека, только когда известен альбом.
    • Качество не имитируется: mp3 = LAME V0/V2 c настоящей m4a-дорожки,
      никогда не upsampling; битрейт в панели = фактический.

## 4. Сбор длинных списков (liked/playlist)

    Порядок дверей: companion LM-джоб → страницный /browse → DOM-скролл.
    • page-fast: вкладка = этот же лист, шапка сказала N строк, N уже в DOM →
      сразу в очередь, без companion/browse/скролла (альбомы, 20-трековики).
    • domOnly: лист, упавший и у companion, и в browse, запоминается в сессии —
      повторные нажатия идут прямо в DOM-сбор.
    • listBusy: параллельные нажатия не плодят вторых сборов; повторная кнопка
      при живой очереди НЕ останавливает её (останавливает только «стоп»).
    • Скроллер: кандидаты (под точкой над списком → контейнер листа → строка →
      обёртки YTM → документ), выбор ПРОБОЙ «запись scrollTop сдвинула?».
      Тупик = эскалация к следующему кандидату; перед сдачей — прыжок в
      настоящий низ (scrollTop=1e9) и последний шанс подгрузки.
    • Пейсинг: шаг 85% вьюпорта, пауза 260 мс, ожидание спиннера НЕ засчитывается
      как «конец списка», watchdog 14 раундов без роста. Прогресс «собрано N из M»
      виден на панели.
    • «Сколько» = cap раннего выхода и в сборе, и в нарезке очереди.

## 5. Клиентская лестница yt-dlp — один источник

    CLIENT_CHAIN = (web_safari, ""=дефолт, tv, web_embedded), добивка
    web_safari+formats=missing_pot (MISSING_POT). url-режим и плейлист
    выводят порядки ИЗ ЭТИХ КОНСТАНТ (тест запрещает рукописные дубли).
    _WIN: победитель сессии идёт первым в обоих дорогах (модульный глобал —
    осознанный долг до 0.7). 404/not found вторым клиентом не лечится (1
    попытка); «похоже на бот-чек» = полная лестница; «account throttled» =
    авто-сдажа без выжигания лимита; host-round www при browse-400.

## 6. Сеть и доступ

    proxy: ytm-dl.ini > системный > none; «0|none|off|direct» = нацело без
    прокси; socks без PySocks = внятный отказ ДО трёх попыток. Cookies:
    auto-поиск cookies.txt рядом с ytm.bat; firefox:путь (портативный разбор
    как у yt-dlp); «тонкий набор» объясняется в self-check. impersonate:
    chrome-отпечаток через curl_cffi. Обложки идут тем же прокси, что и yt-dlp.

## 7. Файлы и наблюдаемость

    ytm-run.log (компаньон + зеркало панели через /log) · ytm-dl-log.txt
    (серверный --log-file) · ytm-dl-error.txt (трейс control.py) ·
    ytm-dl-report.txt (сборка для пересылки). Лог панели = кольцевой,
    «молчание невозможно»: fatal-баннер при поломке UI, mirrorLog при
    каждом нетривиальном решении сбора.

## 8. Версионирование и поставка

    @version userscript == APP_VERSION companions == VER в шапке панели ==
    тег git vX.Y.Z. Обновление: распаковать zip поверх папки + ytm.bat
    restart + userscript на замену. Один entry point: setup.ps1 (+bat-обёртка).
    Поставка: yt-dl-win.zip (сборка) и yt-dl-win-repo.zip (источники+сборка),
    хэш-строка README генерируется сборкой и обязана совпадать с байтами.

## 9. Тесты

    bash tools/run_tests.sh = node --check, py_compile, dist-сборка,
    userscript-синтетика (405), real_mp4 на живом ffmpeg (18), живой
    companion HTTP (602), e2e-конвейер (11). «Никогда снова» (зашито
    юнитами): « (1)» в именах, TRCK=0, HTML вместо медиа, панель очереди
    вместо листа, record-призраки в cfg, две рукописные лестницы.

## 10. Чего система НЕ делает (границы, чтобы не «починить» лишнее)

    • Не качает параллельно несколько треков одной очереди (по просьбе
      владельца транспортный параллелизм не включён).
    • Не пишет номера дорожек-заглушки «для красоты» (см. §3).
    • Не трогает чужие процессы на порту, не просит «сохранить как», не
      выдумывает артиста/альбом, если строка их не принесла.
    • Не меняет сетевой режим системы: inherited proxy — поведение по умолчанию.
